# 季集识别与混版播放列表

集标签、播放 URL 和列表位置分别保留。播放请求仍使用来源返回的 URL／ID；列表位置不是可靠的季集坐标。

## 识别与匹配

共享解析器支持 `S02E03`、`2x03`、`第二季第三集`、`第十二集`、全角数字和常见发行文件名。文件大小、年份、日期、画质、编码、声道及文件哈希不会被当成集号。

上下集、`Part 1/2`、预告、特别篇和多集合并保留各自含义。智能换源不会把“第12集上”匹配到“第12集下”，明确不同的季也不会仅凭集号匹配。多个版本都满足同一集、且没有足够依据区分时，需要用户选择。

来源没有集标签时，界面仍用 `01、02…` 显示位置，但这些生成的号码不会用于自动匹配另一个来源或请求电视剧的元数据、社区跳过。电影识别不需要集号，继续使用原有电影身份链路。

## 同一列表中的多个版本

例如同一来源同时返回：

```text
[494.7MB][ANi] 暗部共生少女 - 01 [1080P][Baha][WEB-DL][AAC AVC].mp4
[1.4GB]Toaru.Anbu.no.Item.S01E01.1080p.WEB-DL.AAC.H264.mkv
[510MB][ANi] 暗部共生少女 - 02 [1080P][Baha][WEB-DL][AAC AVC].mp4
```

下一集、上一集和预加载使用同一个选择器，优先保持当前字幕组、画质、语言和编码对应的版本。播放第一项后会进入第三项，跳过另一个版本的第一集。体积与哈希变化不会单独拆版；手动仍能选择列表中的任意版本。

混版列表中，当前版结束或缺少下一集时不会跳回另一版的第一集，也不会自动跳过缺集。已启用智能跨站下一集时，仍可按原有设置查找目标集，保留当前季与版本偏好。倒序显示、反向播放和后续追加的集列表沿用这套规则。无法可靠解析的普通列表保留来源顺序。

## 弹幕与社区跳过

- 自定义弹幕 API 的 `{episode}`／POST 字段继续传原始集标签，保留既有服务契约。
- Logvar 优先用视频 URL 精确匹配；文件名兜底保留发行信息，未知季不自动补第一季。自动绑定须有唯一且片名、季集一致的候选，其他候选可在手动搜索中选择。
- 社区跳过沿用严格的 TMDB 身份、季数和集数校验。上下集、多集、预告或缺少明确季号的多季剧不会强行请求单集区间；明确的季零特别篇可继续识别。

文件名解析无法独自把动漫绝对集数、日期集或多集合并映射为 TMDB 的季内单集，这些情况需要来源或元数据提供进一步信息。

## 验证范围

JUnit 覆盖季集解析、版本匹配、混版与混季导航、上下集、缺集、倒序和 API 返回候选校验。Android 控制器回归使用受控集列表截获播放请求，并检查 Parcel 和生成标签标记；预加载检查目标选择一致性，不代表真实媒体缓存传递或外部服务匹配成功率。

可通过 GitHub Actions 的 `Build isolated TV validation APKs` 运行完整测试、TV／手机编译和 lint；`TV appearance and touch verification` 的 `episode_navigation=true` 专门执行混版控制器 Android 回归。
