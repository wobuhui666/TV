# 诊断、缓存与播放体验改进

本轮在既有 TV 界面和播放器上吸收 WebHTV 的实用设计。参考评审固定上游提交 `4e30ffaf219b1db15fe5662aeff6f9820e2b32bf`；实现按本项目结构编写，保留现有 OTA、AI 字幕、双字幕、同步及原生首页。

## 使用方法

### 缓存管理

设置 → 缓存管理可查看图片、播放缓存、更新安装包、其他文件的占用，点选某一类清理，或选择“清理可清理项”。正在使用的资源、刚完成的更新包会跳过；结果显示实际释放量、跳过和失败项。其他文件中的脚本、导入数据、EPG 等不会一并删除，配置、历史和用户字体不在清理范围内。

播放器生命周期、后台缓存写入、下载和等待安装分别持有保护租约；所有清理入口共用同一门禁。SimpleCache 通过拥有它的组件清理资源，保留缓存对象与索引，避免直接清掉整目录。没有新增默认自动深度清理。

### 诊断日志

设置 → 诊断与工具 → 诊断日志：

1. 选择“开始记录”，然后复现问题。
2. 返回选择“标记刚才的问题”，保存近期日志窗口。
3. 选择“手机扫码下载”或“分享诊断包”。手机与电视需要在同一局域网。
4. 排查完成后停止记录，或“停止并清除记录”。

统一收集 Jar、JS、Python 和 MPV／播放事件，保留原来的独立日志入口。诊断默认关闭，每次应用进程重新启动后仍为关闭；记录有大小上限，常见 token、Cookie、Authorization、URL 凭据会在存储及导出前处理。导出包含条目大小和 SHA-256，故障快照最多保留三份。对外分享另生成最多三份不复用路径的快照，停止时撤销授权；Python 半行缓冲也按记录会话隔离。

Exo 诊断包含音频解码器、输出格式、AudioTrack 缓冲容量、音频欠载时距上次写入的时间，以及播放位置、媒体缓冲时长和视频丢帧事件。遇到声音或弹幕短暂停顿时，开始记录后复现并标记问题；缓冲容量不等于当前剩余音频，未知的时长保留为 `TIME_UNSET`。`lastOutput` 是最近初始化的输出记录，`releasedOutput` 是该释放事件的配置，避免把晚到的旧输出释放误认为新输出释放。此记录也适用于正式版，关闭记录后没有周期采样。

手机下载地址带随机授权值，十分钟内有效，每次生成新地址替换旧地址；停止记录立即撤销。只提供局域网只读下载，没有远程开启采集或修改配置功能。旧的独立 MPV／JS 日志导出行为保留，统一诊断的脱敏保证只适用于新的诊断包。

### 来源健康与搜索

设置 → 诊断与工具 → 来源健康可查看当前配置中来源最近的搜索／详情状态与耗时；可清除记录，或开启可选的健康排序。排序只影响搜索调度顺序，不改配置文件顺序，不代替现有智能换源和剧集匹配。

健康记录仅保存在当前进程内，最多 512 条，24 小时失效，配置之间隔离。无结果、来源失败、未检查分开显示，取消和应用整体离线不记为来源坏。

搜索全局最多六个实际插件任务，等待来源不会逐个塞进无界执行器队列。新搜索或退出页面会清掉待执行任务，旧结果不会刷新新页面。不响应中断的第三方插件仍会占据原来的槽位，应用不会通过无限新增线程掩盖它；极端情况下需重启应用释放插件。

### 检查网盘链接

设置 → 诊断与工具 → 检查网盘链接，粘贴一个 115／夸克／阿里云盘分享链接，可包含提取码。检查仅请求匿名分享元数据，不登录网盘、不取文件、不启动播放。有效、失效、需提取码、暂不支持、暂时无法确认分别提示；任何结果都不会禁止通过原来源播放。

多实例共用三条网络并发额度、最多 128 条缓存和在途去重记录；每次检查有总时限，可取消。网盘接口变化、风控、网络异常优先显示“暂时无法确认”，检测结果只供参考。

## 播放改进

- 弹幕分块在后台建立有序时间索引，绘制时跳过与当前激活范围不相交的历史分块；仅多个分块命中时排序，查询不再为历史分块创建临时映射或迭代器。历史数据仍保留供回退和重测量使用。
- 当前片预缓存和下一集预载共用一个后台租约，缓冲不足、前台加载和 seek 会抢占取消，租约限时轮转避免长期独占；不根据 localhost 的读取速度盲目增加线程，也不自动改变用户倍速。
- 下一集保留最多 10 秒的预载和原有开关。后台 HTTP 取消会终止真实连接，异步缓存尾部写入在 hole-span 租约释放前继续受保护。
- 临时倍速恢复按下前的真实速度；手机手势取消、多指抢占、离开页面，以及 TV 松键／离开全屏等场景会结束临时倍速。
- 切换内核、软硬解、AI／音效重建和隧道错误恢复后保留速度、音调及暂停状态。
- TV 历史卡与手机历史列表补充准确已播时间，便于替换失效链接后继续观看。

线路当前调用均来自明确点击，保留“点线路切换播放”的现有行为；没有把 active 线路与仅浏览的线路混为一谈后修改自动播放。也没有引入新的 AAC/MP3 vendor-direct、GPU 杜比渲染、WebHome 或公网托管；这些需要独立设备和产品需求验证。
