# 原生海报墙、追更日历、搜索过滤与海报选源

适用于 TV（leanback）界面。全部采用 Android 原生界面，遥控器和触摸均可操作。现有片源、播放引擎、字幕、收藏和观看记录继续沿用。

## 开启与恢复

进入 **设置 → 首页与发现**：

| 选项 | 默认 | 开启后的行为 |
| --- | --- | --- |
| 使用模式 | 媒体库 | 选择媒体库、简洁或经典，静态预览展示布局；返回首页生效。说明见[媒体库模式](media-library.md)。 |
| 首页布局 | 精简首页 | 可选精简首页、旧版来源首页、旧版海报首页。返回首页立即生效；仅切换布局不会重置选源、收藏、历史或云桥配置。 |
| 搜索相关性 | 原有匹配 | 可选“过滤无关结果”或“严格片名匹配”。搜索结果页顶部也能切换。 |
| 海报详情内选源 | 关闭 | 从首页或推荐页进入海报详情后，直接在详情侧栏选择播放来源。 |
| 海报智能匹配 | 关闭 | 海报选源时补查原名，并按片名、别名、年份和季数的匹配程度排列候选。需要同时开启详情内选源。 |
| 播放来源优先级 | 原有顺序 | 为当前配置指定多个常用来源，按所设顺序优先查询和展示；其余可搜索来源继续补充结果。需要开启详情内选源。 |
| 继续观看卡片菜单 | 关闭 | 首页和完整历史页的卡片长按／菜单键打开原生操作菜单，直接继续观看、找其他来源或删除这一条。 |
| 首页我的片单 | 关闭 | 开启海报首页后可独立打开，展示当前配置的点播收藏和全局发现收藏，直接进入原有详情页。 |
| 海报主视觉轮播 | 原有轮播 | 可选“聚焦时暂停”或“仅手动切换”；各模式都保留左右键切换。适用于海报首页和推荐页的主视觉。 |

**恢复原有浏览体验**会切回旧版来源首页，关闭详情选源、智能匹配、继续观看卡片菜单和首页片单，把搜索与主视觉轮播切回原有模式，并清除当前配置的播放来源优先级及云桥地址、密钥。不会删除片源、历史、收藏或其他配置的优先级。切回简洁体验使用 **设置 → 首页与发现 → 使用模式 → 简洁**，返回首页生效；同一入口也可选择经典。已有片源和播放设置继续保留。

## 精简首页

新安装及首次升级默认使用精简首页，之后保持用户选择。顶部为“首页、片库、直播、日历、搜索、我的”；直播按配置显示。原推荐内容收进首页，片库继续独立承载来源分类、目录、筛选和 CK／登录等自定义操作。

媒体库首页依次展示主视觉、继续观看、收藏片单（开启时）、国产电影／国产剧集／此刻热门的小海报行，再展示近一月热门综艺、近一月热门剧集、备受欢迎电影及每日新番的大卡片；大卡下方保留独立小横图。媒体库整排“全部／电影／剧集／高分／筛选找片”已移除，详细找片可从首页底部进入。简洁模式保留分类与筛选行，只加载当前分类的至多三个海报栏目；每行最多 12 部。国产剧优先使用 Rex 当期中文分区榜单，失败时回退到 TMDB 近 30 天播出的国产作品；国产电影热门限定近一年已上映作品，高分榜保留历年作品并另设票数门槛。详细数据及回退规则见 [TV 媒体库体验](media-library.md)。经典模式保留原有入口和内容策略。每个海报行提供“查看全部”。当前源预览最多 20 部影片，自定义操作独立展示，不因缺少海报或预览数量上限而隐藏。

触摸拖动及抬手后的惯性滚动会保留首页位置，晚到的历史、来源或主视觉更新，以及弹窗关闭后的窗口恢复，不会把视口拉回顶部。使用遥控器、点击顶部首页入口或按返回键时，仍按原有导航规则恢复焦点。

“筛选找片”只展示豆瓣／TMDB 条件和分页结果，不重复加载首页的热门海报。电影、剧集入口带入对应类型，高分入口使用评分排序；精选默认豆瓣电影热门。无结果或网络错误时仍能修改条件，返回恢复首页原位置。

换源会立即清除旧源预览及片库分类缓存，旧请求不会覆盖新源。片库尚未加载时提示稍后重试，分类为空时可重新加载或切换来源。豆瓣云桥不可用时依次尝试公开 feed 与独立豆瓣接口；部分服务失败不会阻塞已显示的内容。

TV 包在手机或触屏设备上浏览首页时，手指滑动及惯性滚动后保持当前位置；历史、来源刷新和窗口恢复不会因旧焦点仍在顶部而拉回首页。方向键恢复遥控焦点导航，首页入口与返回键仍可主动回到顶部。

## 追更日历

首页顶部 **日历** 提供 **公开排期 / 我的追更**，默认选中东八区的今天，并在内容加载后聚焦第一部作品。海报左右切换，向上进入日期轨，再向上进入模式与周切换；确认海报进入详情，返回保留原日期与列表位置。切换日期后显示 **今天**，可回到当前周与今天。遥控器和触摸均可操作。

页面采用两层轻量导航、焦点剧集介绍和底部横向海报轨。日期栏左对齐，星期与日号紧凑显示在同一行；不显示长条外框、圆点或横线。未选中日期淡显，所选日期用半透明胶囊，日期焦点随主题反色：深色模式为亮底深字，浅色模式为深底亮字。页面跟随全局浅色／深色外观，浅色使用亮色背景遮罩与深色文字。焦点作品联动全屏背景，介绍区显示已提供的季集、评分、时长、TMDB 提供的播出网络与简介。该日期首次加载的图片决定整轨横卡或竖卡，移动焦点不改变卡片比例；关闭系统动画时切换直接完成。

顶部数据源按钮可选择 **TMDB / Trakt / Bangumi**。TMDB 查询所选日期播出的剧集、动漫和综艺，按热度分页加载。Trakt 使用逐集 UTC 播出时间，换算为东八区日期，保留真实季集号。Bangumi 的 **公开排期** 是当前新番的每周放送表，只显示本周，不据此推算历史或未来单集日期；连接账号后的个人日历按公布的实际单集日期显示 `EP 7`、`EP 7.5` 等集号。

在媒体库或简洁模式的已关联剧集详情点 **追剧**，按钮变为 **已追剧**，作品加入 **我的追更**；再次点击取消。追剧沿用已有收藏，来源收藏与媒体库收藏按同一 TMDB 身份合并。个人日历展示所选周全部已知集日期，同剧同日多集合并显示季与集号，包括特别篇。

没有可播放来源也能添加追剧。未关联 TMDB、没有公布日期或该周没有更新的收藏，可通过 **全部收藏** 查看和管理。请求失败提供重试，部分失败保留已加载内容；排期来自 TMDB，不表示片源已经上线。播出状态按日期显示，未知播出小时不补写时间；缺少评分、播出网络或简介时省略。焦点作品可显示透明艺术标题，缺图或加载失败时显示完整文字标题。

切换到 Trakt 或 Bangumi 后，点 **账号 → 连接账号**：Trakt 先配置应用 Client ID，再用手机打开电视显示的授权地址并输入授权码；Bangumi 使用 [官方令牌页面](https://next.bgm.tv/demo/access-token) 生成个人访问令牌并粘贴。Trakt 应用注册使用 Redirect URI `urn:ietf:wg:oauth:2.0:oob`，不需要 Client Secret；构建时可用 `traktClientId` 或 `TRAKT_CLIENT_ID` 预置 Client ID。Trakt 授权过期时自动刷新；失效或撤销后重新连接。

**账号 → 同步追剧** 将 Trakt 电视剧 watchlist、Bangumi 动画「想看／在看」列表导入当前数据源的 **我的追更**。进入个人日历时最多每五分钟刷新列表；手动同步立即刷新。只有完整获取所有分页后才替换本机账号快照，失败保留旧列表，单集请求部分失败保留成功排期。远端列表和本地收藏独立保存，不上传本地全部收藏，也不自动删除远端项目。

连接账号后，焦点作品右侧可点 **追剧**：Trakt 添加到 watchlist，再点 **取消追剧** 移除；Bangumi 新作品以私密「在看」保存，**搁置** 只将「想看／在看」改为「搁置」，保留评分、标签、隐私和观看进度。已看完作品不会被追剧操作改写。没有 TMDB 关联的条目保持原服务身份，确认海报按片名搜索播放来源，不把 Bangumi 或 Trakt ID 当作 TMDB ID。排期均不表示播放来源已经上线。

账号令牌使用 Android Keystore 加密保存在本机独立存储，不进入收藏、来源配置、备份或 WebDAV；**断开账号** 清除该账号令牌和本机同步列表，不更改远端资料。

界面与追剧操作的验证见 [悬浮日期栏验证](testing/reports/2026-11-20-calendar-floating-dates/README.md)。

## 搜索过滤怎么选

- **原有匹配**保留改版前的匹配行为，并非无限制显示网站返回的全部结果。
- **过滤无关结果**排除仅命中部分短词的噪声和明确年份／季数冲突，保留同系列、片名包含关系与明确别名。
- **严格片名匹配**要求规范化后的完整片名及季／续集编号一致；不会把《Rocky II》当成《Rocky》，也不会把《Matrix》末尾的 `x` 当季数。

繁简体、大小写、常见标点、清晰度后缀和标题中的明确别名会规范化。不会因为简介、演员表中出现搜索词就把一部无关作品判为相关。预告、花絮、解说不确认为正片。来源缺少年份时仍可能显示，需结合名称和季数核对。

切换档位会立即重新筛选本轮已返回的结果，无需重新请求片源。无结果时可切回原有匹配或修改关键词；页面会显示已过滤数量。

## 从海报选源播放

1. 打开首页海报墙，或进入原来的推荐页，选择一张海报。
2. 在详情页点 **选择来源**；开启智能匹配时按钮显示 **智能匹配**。
3. 侧栏只收完整片名或明确别名吻合的来源，逐步显示片源名称、实际片名、年份／更新信息与匹配提示。影评、预告与仅提到片名的相关视频留在完整搜索中。可切换 **按源顺序／匹配优先**，多季剧可选季数。
4. 点一个来源，进入现有播放详情和选集流程。匹配不触发自动播放，也不表示已验证该来源一定能播放。

明确的电影／电视剧类型冲突会被排除；缺类型的结果保留供手动核对。选季时会补查含季数的名称，保留基础片名检索作为兜底；智能模式还会利用元数据中的原名。剧集的首播年不作为所有后续季的年份，以免把后续季误排除。豆瓣详情可先显示和选源，TMDB 补充失败不会阻塞这条路径。

来源查询与普通搜索共享最多六个实际任务槽位，本轮最长 30 秒；最多保留 120 个候选。已经移动到某个来源上时，新结果不会把焦点下的卡片移走。**重新查找**开始新一轮；**完整搜索**可手动改片名；返回键先收起侧栏，再返回海报墙。收起、离开页面会取消排队任务和内置 HTTP 请求。不响应中断的第三方插件仍受原来的实际并发上限约束。

## 指定常用播放来源的优先级

1. 在 **设置 → 首页与发现 → 播放来源优先级** 打开编辑器；也可以从海报详情的选源侧栏点 **来源优先级**。
2. 点 **添加来源**，勾选常用来源，再点 **添加所选**。只能添加当前配置中可搜索的来源。
3. 用每行的 **前移／后移** 调整先后，第一项优先级最高；**移除**只取消该来源的优先级。触摸和遥控器均可操作。
4. 点 **保存**后生效；从选源侧栏保存会立即重新查询。**取消**或返回不会保存草稿。

例如设为“来源 B → 来源 A”：会优先安排 B、A 的片名查询；开启智能匹配时，它们的原名查询也优先安排。结果中 B 排在 A 前面，其他来源仍可提供兜底。请求并发执行，晚返回的优先来源仍可进入前列；遥控器停在结果卡片上时先保持位置，移到侧栏控制按钮后再应用新顺序。优先来源会显示“优先 1”等标记。

明确指定的来源顺序优先于智能匹配排序，同一来源内继续按所选匹配模式排序。片名、电影年份、季数和明确类型的冲突仍会过滤，来源优先不会把无关剧集变成匹配项。某个常用来源失败、没有本片或只返回错误版本时，可继续选其他来源；最后仍由你点选播放，不会自动开播。

顺序按配置分别保存，换回同一配置会取回自己的设置。尚未加载或不可搜索的来源会跳过，单纯重载配置不会清空已存顺序。想单独撤销优先级，点 **恢复默认顺序 → 保存**，即可恢复原来的查询与结果顺序；也可以使用上面的 **恢复原有浏览体验**。

播放中的季集匹配会区分上下集、明确季号与发行版本。同一来源把不同字幕组或画质的版本放在一个列表时，自动连播与预加载优先沿用当前版；列表位置补出的数字不作为可靠集号。处理方式与验证范围见 [季集识别与混版播放列表](episode-matching.md)。

## 海报墙操作

精简首页顶部保留搜索、片库、直播、日历和我的入口；旧版布局继续提供原推荐入口。主视觉左右切换，向下进入分类和海报棚，确认进入详情。继续观看保持原来的续播记录。没有配置播放源时也能浏览推荐，播放前再配置来源。

切换首页分类或从触摸返回遥控器导航时，先进入内容区，再随目标行的绑定与定位恢复焦点。片库仍打开当前片源自己的分类和目录。

切换首页分类或从触摸返回遥控器导航时，通过目标行选择恢复焦点，已获得焦点的行保持当前位置。片库仍打开当前片源自己的分类和目录。

豆瓣与 TMDB 独立加载；某个服务失败时保留其他已加载内容。首页本轮加载最长 24 秒，失败后可从页面末尾重试，也可继续使用顶部入口。推荐数据只是选片信息，实际播放仍来自自己配置的片源。

### 继续观看卡片菜单

开启后，短按卡片仍继续播放；长按确认键或按遥控器菜单键，会看到片名、集数、已播时间与来源。菜单默认停在“继续观看”，也可选择“查找其他来源”或“删除这一条”。查找来源不会清除原来的观看记录；关闭菜单会回到原卡片，删除后移动到邻近卡片，删空时仍可回到页面导航。

删除始终针对打开菜单时的那一条记录和配置。菜单打开后切换配置、列表刷新或长按松键，都不会把操作变成清空历史。关闭这个选项后恢复原来的长按交互。

### 首页我的片单

使用精简首页或旧版海报首页时，设置中会显示“首页我的片单”。它复用现有收藏：本配置的点播收藏与全局的发现收藏，按最近收藏排序，首页最多显示 20 项，更多内容进入“查看全部”。点一张海报直接进入它原有的点播或发现详情。

片单从本地读取，离线也可显示；收藏、取消收藏后返回首页会刷新。读取失败时保留同配置已显示的片单并提供重试；切换配置不会留下上一配置的收藏供误点。关闭此行只隐藏展示，不会取消收藏。

### 主视觉轮播

- **原有轮播**：保持原来的七秒自动切换。
- **聚焦时暂停**：遥控器停在主视觉卡片上时保持当前影片，移开后重新计时。
- **仅手动切换**：只用左右键选片，不自动切换。

打开菜单、进入后台或离开页面时会停止计时；返回后只安排一次新的轮播。片名和确认目标同步更新，图片加载慢或失败也不会让确认操作进入另一部影片。

## TMDB 网络兼容

在 **设置 → 来源 → TMDB 连接方式** 选择默认反代、直连官方或自定义反代。旧版已保存的自定义地址会自动保持为自定义模式；在默认反代与直连之间切换不会清除保存的地址。

默认反代使用 `https://t.coolmarket.eu.org/`，按部署的网络分流由 Vercel 或 Cloudflare Worker 提供服务。社区片头片尾的身份识别支持该代理声明的名称清理结果，具体核验规则见 [社区跳过说明](community-skip.md)。已保存的自定义地址保持原配置，可在此切换回默认反代。

直连使用 `https://api.themoviedb.org/3/` 获取资料、`https://image.tmdb.org/t/p/` 加载图片，不会自动切到第三方反代，也不使用 Cloudflare 边缘回退。用户配置的 DNS、hosts 和网络代理规则继续适用。自定义模式显示地址编辑入口，留空时使用默认反代。切换连接方式会清理推荐与路由缓存，返回首页后重新加载。

在 ARM64 redroid Android 测试环境的网络中，自定义反代域和优选域都解析到同一组不可达的 Cloudflare IP，出现 TCP 超时；另一默认反代出现 TLS 连接重置。保持原反代域名与严格证书校验，使用可达的标准 Cloudflare 边缘后，该环境中的请求返回 HTTP 200。

**验证环境勘误（2026-10-08）：**此前仅按系统报出的 `ro.product.model=SM-F900F` 将该端点标为“三星真机”。对同一 ADB 端点补查发现 `ro.hardware=redroid`，网络接口为容器 veth，应归类为 redroid Android 测试环境。这些网络现象和修复结果仅描述该环境，不能推广为实体三星设备的兼容性结论。

**设置 → 来源 → TMDB 网络兼容**默认开启，也可单独关闭。仅在 TMDB 元数据／图片的原路失败，且 DNS 结果确认为 Cloudflare 网段时尝试有限的边缘路由；保留原 URL、Host、SNI 与证书校验，不切换到另一家反代，不把 API key 发送给其他域名。显式 hosts 与代理设置优先。成功路线短期缓存，失效后回到正常路由。

同时修复首次兑现 DoH 设置时重复清理路由缓存、导致 DNS 任务中断与域名规则首次加载失败的竞态；真正切换网络设置仍会刷新缓存。

该开关属于网络修复，不随“恢复原有浏览体验”关闭。它不解决反代服务本身停机、失效 API key、登录验证或所有网络均不可达的问题。
