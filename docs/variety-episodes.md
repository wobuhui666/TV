# 综艺日期、期号与版本

综艺列表中的播出日期、期号和列表位置分别保留。播放请求继续使用来源返回的 URL／ID；应用不会把日期或界面位置换算成 TMDB 的季内集号。

## 标签识别

共享解析器从原始标签识别以下信息，并缓存解析结果供选集和接口使用：

| 原始标签示例 | 保留的信息 |
| --- | --- |
| `20260301`、`2026-03-01`、`2026年3月1日` | 相同的有效播出日期 `2026-03-01`。 |
| `第3期`、`第三期` | 期号 3，保留“期”的标记。 |
| `2026-03-01 第3期（上期）` | 日期、期号和上期。上／中／下期、上半期及原有 `Part 1/2` 可分别识别。 |
| `第3期会员版`、`第3期（纯享版）`、`第3期 加更` | 会员、纯享和加更分别保存，不与正片合并。 |
| `第3期 未播版`、`第3期 幕后版` | 幕后版本；花絮还保留预告／短片标记。 |

正片、完整版和没有内容版本标记的条目使用普通版本。发行组、语言、画质和编码仍沿用已有的发行版本识别。组合标记会一起保留，例如会员加更不会只剩期号。

日期会检查真实日历和闰年。无效日期、多个冲突日期、合并上下期、多集范围或其他含义不明确的标签不能自动当成一个可靠单集。发行文件的目录日期、体积、画质和哈希不会单独成为播出日期或集号。无法识别的标签仍显示来源原文，用户可以手动选择。

来源只返回 URL 时，界面生成的 `01、02…` 仍是列表位置，不用于跨来源的自动期号匹配或电视剧元数据请求。未知季号保持未知，只有已有信息可以确认时才补充季数。

## 换源与续播

日期、分段和内容版本参与目标核验，避免同一数字落到另一条内容上：

| 当前目标与候选 | 自动匹配 |
| --- | --- |
| `20260301 第3期` ↔ `2026年3月1日 第3期 正片` | 可以，日期和已知期号一致。 |
| `2026-03-01 第3期` ↔ `2026-03-08 第3期` | 拒绝，日期不同。 |
| `20260301` ↔ `2026-03-01 第3期` | 可以，日期一致，缺少的期号不构成矛盾。 |
| `20260301` ↔ `第3期` | 拒绝，没有可验证的日期对应关系。 |
| `第3期（上期）` ↔ `第3期（下期）` | 拒绝，分段不同。 |
| `第3期` ↔ `第3期会员版` | 拒绝，内容版本不同。 |

双方都提供期号时，期号也必须一致；明确的不同季号、预告与正片、特别篇与普通条目继续分别核验。多个等价候选具有不同播放 URL 且无法进一步区分时，不自动选第一个。

结构化目标查找失败时，不会因新来源只有一条内容就直接播放，也不会退到保存的列表位置或第一条。手动选集可以明确指定任意条目；已知播放 URL 可以保留这个明确选择，但不会覆盖已知日期或版本的冲突。

## 连播与预加载

上一集、下一集和预加载使用同一个目标选择器，并保留当前内容版本和发行版本。下面的列表播放第一项后，会先进入第三项，再进入第五项：

```text
2026-03-01 第3期（上期）
2026-03-01 第3期 加更
2026-03-01 第3期（下期）
2026-03-08 第4期 纯享版
2026-03-08 第4期（上期）
2026-03-08 第4期（下期）
```

日期列表按实际存在的下一播出日期前进，上例不尝试寻找 `2026-03-02`。只有期号的列表继续要求相邻期号，不跳过缺期。整期和拆分上下期分别连播，不自动从整期转入同一期的拆分版本。

倒序列表和反向播放遵循同样规则。缺少对应版本、日期／分段排列相互冲突，或下一目标有多个无法区分的 URL 时，保持当前条目。手动选择后可以从所选条目继续。标签没有足够信息时，原有普通列表仍按来源顺序处理。

## 弹幕、字幕与社区跳过

**Logvar** 保留视频 URL 精确匹配入口；使用标签查询综艺时，走 `/search/episodes` 并传完整原始标签，不拼成 `S01E03`。自动接受结果前，核验片名、已知季号／年份、日期、期号、分段、内容版本，并要求候选唯一。

Logvar 的候选核验比普通换源更保守：请求是 `第3期` 时，返回的 `第3集` 或裸数字 `3` 不能证明是同一期；日期标签的候选缺少日期、期号有一方缺失或版本不同，也不会自动绑定。没有可靠候选时，可在弹幕搜索中手动选择。

**原有自定义弹幕 API** 的占位符和 POST 字段继续收到原始标签，保留既有契约及繁简转换。简单期号可以沿用旧接口；日期、上下期、加更／会员／纯享等复杂标签不再自动加载旧接口的第一条结果，仍可手动搜索和选择。

**ASSRT 在线字幕** 的默认搜索词保留综艺原文，例如 `节目名 2026-03-01 第3期（上期）会员版`。用户仍需根据文件名、语言和版本选择字幕；普通电视剧继续使用已有的季集搜索格式。

**社区片头片尾跳过** 不把已识别的综艺日期、期号或内容版本提交给普通 TMDB 季集匹配链。可靠的期号与 TMDB 季内集号映射尚未实现；手动片头／片尾设置继续可用。

## 验证

JUnit 覆盖日期别名、闰年、冲突日期、期号、上下期、内容版本、换源与连播，以及 Logvar 和旧 API 的候选核验。Android 回归用受控播放列表检查真实控制器、历史／Parcel、手动选择、预加载目标一致性，使用本机 HTTP 服务检查 Logvar 请求和 ASSRT 搜索界面。

GitHub Actions 的 `Build isolated TV validation APKs` 运行单元测试、TV／手机编译及 lint；`TV appearance and touch verification` 的 `variety_episodes=true` 在 API 34 模拟器中执行 7 组、共 61 项相关 Android 回归，并按每组数量校验。日志和界面证据保存在 `variety-episodes` 产物目录。

这些回归证明受控样例的标签和播放目标处理，不代表外部服务的匹配成功率、所有来源命名方式或实际字幕同步效果。普通剧集与发行混版规则见 [季集识别与混版播放列表](episode-matching.md)。
