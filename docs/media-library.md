# TV 媒体库体验

在 **设置 → 首页与发现 → 使用模式** 选择完整体验。首次安装和从旧版升级均默认使用「媒体库」；已有片源、播放、字幕、解码设置继续保留。三种模式提供统一的静态微缩界面预览，由代码绘制，不请求网络图片。

**「媒体库」目前仍可能不稳定，也可能不好用。遇到卡顿、崩溃、选源或操作问题，欢迎到 [Issues](https://github.com/wobuhui666/TV/issues) 反馈。切回简洁体验：设置 → 首页与发现 → 使用模式 → 简洁，选择后返回首页生效；同一入口也可选择「经典」。**

媒体库和简洁模式将推荐精选合入首页，顶部保留「首页、片库、直播、搜索、我的」，直播按配置显示。默认精选为「国产电影、国产剧集、此刻热门」三行，以国产内容为主并保留少量全球热门推荐，每行最多 12 部；电影、剧集和高分类目各显示自己的少量栏目，更多作品通过「查看全部」或「筛选找片」浏览。国产栏目使用 TMDB 的中国产地条件，高分栏目另设有效票数门槛，不按中文片名判断产地。

首页「片库」始终打开当前片源自己的分类、列表和筛选；源提供的登录／Cookie 操作与账号文件夹继续由该源处理。首页只加载当前类目的至多三个精选栏目，复用原有缓存、24 秒截止与退出取消机制。「筛选找片」支持类型、产地、年份与评分等条件。

原生片库的列表项目保留原有配置、详情和播放入口；普通海报项目可进入媒体库详情。列表详情继续复用已获取的数据，并在离开所属页面后取消交互。

| 模式 | 浏览与搜索 | 详情与播放 |
| --- | --- | --- |
| 媒体库 | TMDB 作品优先，片源补充播放资源与独有内容；操作首页背景时暂停轮播 | 全幅背景、播放按钮、季集、资源、演员、分类、预告、剧照与相似作品 |
| 简洁 | 同一套作品和片源搜索；首页背景手动切换 | 保留简介、播放、季集和资源；「更多资料」展开演员与附加内容 |
| 经典 | 原有片源目录和搜索 | 原有详情、小窗及播放操作 |

## 配置

TMDB 沿用项目已有配置。构建时通过环境变量 `TMDB_API_KEY` 或 `local.properties` 中的 `tmdbApiKey` 提供密钥（见 `app/build.gradle`）；连接方式、代理地址仍在设置中配置。密钥不得写入源码或提交的文件。缺少密钥或 TMDB 暂时不可达时，搜索保留片源结果；详情保留已知资料和可手动选择的片源。

TMDB 搜索同时覆盖电影和剧集，并支持筛选与分页。同名但年份、类型或季数冲突的资源不会自动挂到作品；不确定的关联保留为片源补充。可在设置或详情菜单调整片源优先级。

搜索输入页在后台读取热词与历史记录，界面最多显示 30 个热词与 9 条历史；聚焦麦克风只选中按钮，点击或按确认键才启动语音。作品搜索的响应解析、片源关联和批量合并也在后台完成，结果列表回收可见卡片。搜索和推荐直接复用 App 的 Rex 海报组件，海报为 2:3，标题与年份／资源数量合为两行；离开页面或切换筛选会取消旧任务并丢弃迟到结果。

搜索结果顶部直接切换「全部／电影／剧集」，有片源补充时可通过「片源」按钮定位。首排结果按上键返回当前筛选，筛选栏按下键进入结果；用户开始操作后，后续结果不会主动抢走焦点。

片源搜索返回的目录与账号操作保留为整行列表，可逐层进入源自己的内容，返回后回到原条目。它们不计作作品的可播放资源；没有海报时显示目录图标，没有 `vod_id` 的合法账号操作也可使用。电影／剧集筛选不会隐藏这些入口。

## 遥控器操作

- 首页切换分类或从触摸返回遥控器导航时，目标行先滚入屏幕并完成绑定，再交接焦点。「片库」继续打开当前片源自己的分类和目录。
- 打开详情后自动核对当前作品与季集，预获取确认资源的直链；点击主播放按钮才进入全屏。按钮显示待播集数，续播时显示已看集数和进度；浏览其他剧集只改变浏览焦点和预获取目标，不改主按钮的续播目标。点击剧集卡播放该集，尚未播出的卡片显示提示。
- 详情主播放按钮按下键先进入换源、收藏等快捷操作，再按下进入当前集；没有对应卡片时进入季／线路选择。剧集卡按上键回到季选择，再按上键回主播放按钮。「全部剧集」可定位指定集；切季立即移除旧季卡片，加载时保留季选择。TMDB 分集每组 30 集，未关联 TMDB 的原始列表按线路分组、每组 40 集，均使用横向卡片与区间选择。
- 主播放按钮优先续用已观看资源，并参考片源优先级与可靠性。自动选源总等待时间最多 30 秒，单个自动详情请求最多 10 秒；失败会尝试其他匹配资源。选择中主按钮显示「取消加载」，再次确认可取消；点击另一资源会取消旧请求并直接选择新资源。手动详情请求使用原有 30 秒超时并允许片源交互。退出页面或取消选择会丢弃迟到响应。
- 下方资源卡可手动选择，并按来源标题或备注中的 1080P／4K 线索筛选；实际音画规格以开播后的播放器信息为准。电影有多个剪辑或文件时展开原始列表，不确定的季集保留原始选择；手动选定的资源失败后返回详情。
- 全屏播放时，上下键打开控制栏；缓冲期间也可打开。标题显示作品名，下方显示当前集与片源／线路，文件或版本名称保留。「选集」直接打开当前线路的集列表，并定位当前集，选择后保持全屏。「播放列表」中的「线路／画质」仅在存在多个可选项时显示；单集不显示选集和上一集／下一集。按返回先关闭选择面板并恢复控制焦点。
- 确认键在播放画面暂停／继续，缓冲尚未就绪时打开控制栏；左右键快退／快进。控制栏进度条左右键调整，确认提交，返回取消未提交的调整。已确认季集的上一集／下一集按明确集号移动，缺集或多版本歧义不会跳到相邻文件。
- 播放默认进入全屏。返回时保存进度并回到同一详情页，恢复原先的剧集或资源焦点。隐身模式仅在当前页面带回进度，不写入观看记录。
- 播放器里的「换源」带回当前进度，并聚焦详情页的统一资源列表；选择另一个资源后继续播放。
- 演员打开其作品列表，分类打开对应筛选，剧照可左右翻页，预告片通过支持链接的外部应用打开。
- 剧集、资源、演员与推荐沿用 App 的 MiSans 字体、圆角和焦点描边。预告与剧照使用 16:9，演员为圆形头像，剧照只显示图片；相似作品为海报与简介组合横卡。系统关闭动画时停止背景位移，方向键导航继续可用。

## 滚动与外观

媒体库与简洁模式的详情使用 Compose TV：左侧显示片名或透明 Logo、已有评分与三行简介，右侧集中放置播放与快捷操作。播放按钮宽 220dp、高 52dp，图标与文字组合居中；下方 44dp 圆形快捷按钮在同宽操作组内居中排列。主操作保持 App 的中性高亮，资源等次级卡片使用半透明表面；背景取色只在全局深色、浅色或跟随系统主题内调整色温。缺少评分、厂牌 Logo 或资料时省略对应内容，简介可展开，媒体信息只展示当前已有资料。

剧集标题栏与图片轨道的首张卡片左缘对齐，季选择和「全部剧集」按钮统一为 44dp 高，与标题垂直居中。选集卡宽 240dp，缩略图保持 16:9，细焦点描边仅包围图片。下方文字没有整卡背景，紧凑左对齐：日期独立一行，集数与时长共用一行，随后显示加粗分集标题和最多两行简介。缺少日期、时长、标题或简介时省略对应内容；原始片源保留已有集名与线路名称。

详情采用纵向与横向回收列表，左右安全边距为 48dp、上下为 36dp。背景图按显示尺寸解码，取色在后台进行并缓存；向下滚动时只调整遮罩和轻微位移／缩放，不生成实时模糊图或重建整页。移出列表的图片请求会取消，关闭详情会清理页面请求与资源。切换外观保留当前页面、剧集焦点和滚动位置。

详情不显示时钟、顶部状态栏、返回按钮或吸顶标题，返回使用遥控器 Back 键。方向键使选中卡片留在安全边距内；从播放页返回后按稳定的作品／剧集／片源标识恢复焦点。搜索和图库继续使用各自的现有界面。

## Logo、更新与预获取

剧集 Logo 优先中文，再尝试原语言、英文与无语言图片。已有资料缺少 Logo 时读取无语言过滤的 TMDB 图片接口；图片失败可重试，仍无 Logo 则显示文字标题。动漫和剧集显示当前季的更新集号、该季总集数、下集日期；不把全剧所有季的总数当成本季总数，遇到不一致的资料省略分母。

页面和剧集焦点预获取最多一个确认资源的直链，10 秒请求超时、60 秒缓存有效期。更换集数或离开页面会取消旧请求；点击后一次性交接，核对配置、作品、片源、线路和真实 URL。预获取不会创建媒体播放器或启动解码，嗅探、解析、DRM 和特殊提取器链接继续在点击后的原播放流程处理。手动选择的绝对编号不会在没有证据时写成 TMDB 的季内集号。

## 数据兼容

Room 数据库从 38 增至 39，仅增加 `History.mediaRef/mediaSeason/mediaEpisode` 和 `Keep.mediaRef`。旧记录与收藏保留，不按名称批量推断 TMDB 关联；旧备份缺少新增字段时仍可读取。新备份和同步携带这些字段，合并记录会区分作品、季数与集数，并通过作品身份识别不同译名。未确认的原始剧集不会覆盖已确认的集数；排队保存或删除记录继续使用记录所属的配置。

## 验证

2026-11-16 的详情对齐与普通 TLS provider 修订已完成有限回归：12 项单测、2 项离线生命周期、4 项 Preview 交互、10 次真实详情往返，以及严格和共享客户端各 34 次加密连接、1536 个证书副本压力回归通过。详情与两组压力运行于三个独立进程，未完成同一 PID 的详情与证书压力组合验收；API 31 使用 finalizer 回退，Registry 回调未覆盖。最终 ARM64 Debug 主包的三张详情截图和完整下载已核对，旧失败与实体电视限制保留，见[详情对齐与稳定性报告](testing/reports/2026-11-16-library-alignment-stability/README.md)。这些结果属于详情/TLS 阶段，不能替代新首页或发布包验收。

合并源码的验证使用 GitHub Actions。常规任务包括 `:app:testLeanbackArm64_v8aDebugUnitTest`、TV/mobile Debug 构建及 TV lint；lint 按既有 108 个错误的基线检查新增错误。`LibraryExperienceAndroidTest` 使用隔离 Preview 包和离线 TMDB、片源、图片夹具，核对焦点、季集、取消、失败回退、续播和返回。

在 TV appearance and touch verification 工作流同时选择 `compact_home=true`、`library_native_probe=true`，可使用 API 31 原生 x86_64 JNI 先检查真实 TLS 与两种证书 provider 的释放压力，再运行离线首页、模式、媒体库、数据库、目录和表单回归。测试核对安装包与夹具哈希，保留失败诊断。这个对照不加载真实片源，不能证明 ARM 电视稳定性或先前崩溃的根因。

历史页面、播放与配置验证分别见[搜索报告](testing/reports/2026-11-14-library-search/README.md)、[操作打磨报告](testing/reports/2026-11-15-library-polish/README.md)和[详情重做报告](testing/reports/2026-11-15-library-detail-redesign/README.md)。早期 API 24 UI 包裁剪了 ARM 原生库与 Python，后续 API 31 使用完整 ARM64 包和转译桥；具体提交、截图与覆盖范围以各报告为准。实体电视帧率、全部片源播放、账号登录及真实 Cookie 提交仍未全面验证。
